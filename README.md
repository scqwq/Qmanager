# Qman / QQArchive — QQ 本地媒体管理

## 0.6.5：从备份历史打开保存位置

展开备份历史中的“保存位置”，点击路径即可打开文件资源管理器；目录包打开该文件夹，ZIP打开所在文件夹。位置已移走或不可访问时提示重新定位。数据库位置保持在当前Windows用户的AppData目录，不随EXE移动。

## 0.6.4：所选文件自动补足核对

删除和备份会对本次所选文件主动补足稳定性核对，无需靠等待定时更新或反复全盘检查凑次数。页面显示核对轮次、等待和内容检查进度，可取消；变化或不可读项目仍跳过，删除仍需查看清单并明确确认。

## 0.6.3：视频封面与年/月导航归档

本版统一版本号为0.6.3，包含视频卡片关联封面、独立封面默认隐藏，以及此前侧边栏年/月切换和选月不改变年份的修正。默认备份保留封面、删除视频不联动封面；数据库结构及面板样式保持现有约定。

## 0.6.1 补充：视频关联封面

视频卡片使用同来源、同月份、同标识的关联封面，点击仍播放视频。独立封面默认隐藏，角色选择“视频封面”才显示；默认全部角色备份仍保留范围内封面，删除视频不连带回收封面。沿用数据库结构与现有面板样式，匹配不明确或封面不可用时保留原占位。

## 0.6.1：侧边栏年份/月切换

全部年份下选某个月，只筛选这个月，不会自动修改年份或收窄月份列表；只有主动选择年份才限定月份选项，侧边栏与顶部一致。

点击侧边栏“来源月份”切换为“来源年份”，再点切回。选中年份后立即显示该年媒体，切回月份只列出该年份；“全部月份”保留所选年份，“全部年份”清除年/月。顶部筛选同步，标题不追加年份或装饰。月份13px、年份字号保持，标题上方留白缩至原来的3/4；发现日期及独立备份视图沿用相同规则。

## 0.6.0：跨年月份导航与本地诊断

侧边栏保留当前媒体类型的全部来源/发现月份；切换到往年后，仍可直接点击其他年份的月份。顶部月份下拉按所选年份筛选，侧边栏“全部月份”同时清除年份限制。独立备份浏览使用相同行为。

本版一并包含媒体阴影与深浅主题/背景图设置、Windows回收回调生命周期修复，以及设置末尾的本机运行日志；QQ回收前仍须完全退出，明确提示目前不区分账号。日志只在本机保留与轮换，不自动上传。真实QQ操作及完整原生窗口验收边界见使用说明和PROGRESS。

设置页的“备份应用记录”导出清单、观察/操作记录的数据和索引查询缓存，不包含原媒体。按钮旁圆圈问号提供说明。备份历史将备份包/本地源文件合并显示为符号，悬停或聚焦查看含义与检查时间；回收按阶段显示，新加载直接显示已保存的时间，旧记录不补造时间。

主页来源详情位于右上“加载备份”左侧，更新与监控按钮和当前状态同栏。微软雅黑优先、字号适度增加；长提示换行，按钮不随背景增高。操作结果与当前状态分开，错误保留原始原因和处理建议。

## 0.4.5：备份历史状态与操作结果

历史中直接显示备份包是否在登记位置、本地原文件最近核对状态、原文件清理结果和最近恢复结果。补回、相同跳过、冲突另存、仅Qman保存、部分完成/失败/取消/中断分开显示，附带数量和时间；删除备份包不会抹掉恢复结果。

点“核对原文件”只检查这份成功备份对应的原路径与大小，不全账号扫描、不修改媒体索引或读取内容。断盘/未关联来源为未知，外部或媒体页改动后需重查；存在不证明内容完整或QQ识别，操作记录也不代表文件此刻仍在。

## 0.4.4：首次选择目录自动同步设置

默认备份保存目录为空时，首次选定保存位置（或使用已选位置开始导出）会自动同步到设置。默认QQ目录为空时，首次选择读取源或加载备份的目标也会记住；已有默认值不被临时选择覆盖。

加载备份会按默认QQ目录自动填入目标Tencent Files，仍须核对账号和确认退出QQ；可切换为仅保存到Qman。默认目录若是账号/nt_data等子目录，仅向上取同路径Tencent Files祖先，没有可靠根时手动选择，不猜别处。

## 0.4.3：设置与默认目录

侧边栏底部“设置”可预设默认QQ数据文件夹和备份保存目录，支持手输路径、选择/新建保存目录、清除、保存及撤销修改。保存后重开保留，保存本身不扫描或导入；点“导入默认目录”识别账号，再手动快速更新。

备份弹窗优先使用默认保存目录；临时另选不覆盖默认，清除默认后沿用上次位置。默认来源即使尚未导入，也禁止向其内部备份；设置/实际操作均核对目录隔离。网盘上传尚未接入，仍是待讨论事项。

## 0.4.2：可选删除备份历史

删除本地备份包后，每行提供“删除此条记录”；仅在当前位置仍确认缺失时启用。再次确认会移除该行及私有备份清单/原文件关联，不能再从该记录清理原文件；关联尚未执行的清理预检会失效。原文件、已加载媒体和独立操作结果保留，已删除历史不会在重开时重建。若保有完整备份包，可用“加载备份”重新登记。

## 0.4.1：备份本地位置同步

备份历史打开、重新聚焦或“刷新本地状态”时检查登记位置，区分位置存在（内容未校验）、未找到、不可访问和待处理删除暂存。整个文件夹/ZIP被手动删除且父目录可访问时，再确认删除只更新本地清理状态，不再报路径不存在；历史和原文件关联保留。移动/改名需重新定位，离线/权限不足不认定已删除，同路径重新出现仍完整校验。

这是位置检查，不是实时文件夹监控：包内文件删改、云盘和独立副本、登记时数量/大小不自动联动，详见使用说明的同步边界；加载/删除仍完整校验。

## 0.4.0：原目录树＋精简逐文件清单

目录与ZIP备份都按原路径保存媒体：Tencent Files/账号/nt_qq/nt_data/Pic/月份/...；同内容在多个位置也各复制一份，不去重、不用硬链接共用。backup.json只保存公共说明，.qman/files.jsonl按目录引用逐行保存文件名、大小、SHA-256、原实例、首次发现等必要证据，不导出一个带缩进的完整逐文件JSON大对象。无账号映射的单媒体目录使用Media树。

读取、校验、按账号合并恢复、独立查看、历史重新定位/批量删包/原文件清理已配套新格式。元数据留在备份包，不写进QQ；相同目标路径同内容跳过、不同内容另存。请整体保留包内目录及两份元数据。按本轮用户要求，不迁移/适配已生成旧v1包，也不自动改动旧包；本版新建备份为qman-media-tree v2。

## 0.3.5：缓存优先补新与按范围核对备份

查询和筛选直接使用SQLite索引。“快速更新”枚举受支持媒体目录的文件名，与缓存路径集合比较，仅识别新增；不再领取全账号历史待稳定队列。已有记录的内容替换、外部删除留待“全盘更新”核对；运行时明确变化通知仍按具体路径处理，每两分钟轻量补新。名字枚举和首次识别仍有成本，不承诺大账号秒开。

备份区分可直接备份、待核对候选和不能纳入项；只有待核对候选也可点击“核对并备份”。任务冻结本次筛选实例，先对这些文件补齐真实间隔观察，再复制、SHA-256校验。变化/不可读项保留排除原因，无可用项不发布，不等待全账号队列。保存目录可新建并记住，弹窗在索引变化后刷新，也可手动盘点。

前台更新显示“终止更新”，后台显示“暂停监控”，均保留已提交索引。修复旧定时通知导致的休眠误报；真实通知异常或观察停顿仍报告原因。来源日期/首批baseline/备份加载日期语义不变，不以加载日替代首次发现。

## 0.3.2：备份历史中的原文件清理

备份只复制，不自动删源。历史新增“清理对应原文件”，可选择同一原来源的 1～100 份备份，以实际成功条目的原实例和 SHA-256 固定预检，明确确认后移至 Windows 回收站；已变化、新增、重新出现或当时未备份的文件不清理，恢复副本不连带清理。

“删除本地备份包”仍独立、永久删除导出的目录/ZIP；历史清单与原文件清理结果继续保留，所以包已删也可预检。云盘由用户自行保存与确认，程序不验证远端。未在本机关联的原来源不自动猜测，迁移/替换实例请在媒体页手动核对。详见 [使用说明](docs/USER_GUIDE.md)。

当前版本 **0.6.5**，Windows 桌面试用构建。使用 Go、Wails v2、Vue 3 / TypeScript 和 SQLite，在本机管理 QQ 已保存的图片、视频、收到的表情及语音原文件。

盘点、监控和备份保持源只读；“加载备份”是显式例外，可在确认的 Tencent Files 下新增媒体，已有文件不覆盖。不登录、注入或修改 QQ 程序，不解密消息、不上传媒体；媒体页显式确认后可移至 Windows 回收站，不提供永久源删除或自动清理。创建备份和恢复副本都会增加空间占用。

## 直接运行

关闭旧版窗口，打开当前修正版 `build/bin/Qman-0.6.5.exe`，或解压 `build/releases/Qman-0.6.5-win-x64.zip` 后运行包内Qman.exe。产品版本0.6.5，包含保存位置打开、所选文件按需稳定性核对、月份自动回填年份修正及视频关联封面；旧预览成品保留。构建产物不纳入Git，新克隆需先构建。

运行需要 Microsoft Edge WebView2 Runtime；用户不需要安装 Go、Node.js 或数据库服务。完整操作见 [使用说明](docs/USER_GUIDE.md)。

1. 点击 **选择 QQ 数据文件夹**，可选择最外层 `Tencent Files`、迁移后的父目录、账号目录或 `nt_data`，也支持单独的 Pic / Video / emoji-recv / Ptt。
2. 程序有界发现账号媒体根，在左侧切换来源。目录名仅作标识，可自行命名，不代表已验证昵称或聊天归属。
3. 点击 **快速更新** 建立/补充清单并监控。已有索引的账号直接分页显示旧清单，重开不自动扫描；需要核对旧文件变化和缺失时点击 **全盘更新**。
4. **全部类型**表示当前来源的全部媒体类型。顶部月份下拉与侧边栏同步；可再按角色、状态和大小筛选。

## 月份和日期怎样理解

| 入口 | 含义 |
| --- | --- |
| 来源月份 | 文件夹 YYYY-MM 标签，不保证是发送月、下载月或拍摄月 |
| 新增发现日期 | 本工具首次发现后续新增实例的日期，不是 QQ 下载时间 |
| 包含首次导入记录 | 显式纳入首批扫描已有文件，按原首次索引日期查找；仍标“扫描前已存在” |
| 文件系统创建/修改时间 | 可在详情查看，仅作辅助证据 |

日期更改后自动筛选，也可点击“查询”。如果首次导入当天查不到，检查“包含首次导入记录”；默认新增视图会排除基线旧文件。日期区间包含结束日；选择月份会清除日期区间，输入日期会清除月份限制，避免互相排斥。筛选不改写任何历史时间或源文件。

## 只读索引与磁盘数据

运行时沿用 SQLite，不需要 Redis，也不使用 Git 存放媒体。监控在既有索引上补充变化：原生通知按受影响路径更新，每 **2 分钟**只按目录名字补新，不自动全量；旧普通文件沿用缓存，具体变化通知的目标仍核对，手动全盘才核对全部旧记录。稳定性检查仅是启发式，不证明完整下载。

| 数据 | 默认位置 | 用途与保留原则 |
| --- | --- | --- |
| 索引、查询缓存、观察历史 | `%LOCALAPPDATA%/Qman/catalog.sqlite` | 只保存元信息及历史，不保存原媒体；包含不能靠源文件准确重建的首次发现证据，不能当普通缓存随意删除 |
| SQLite 临时事务文件 | 同目录的 `catalog.sqlite-journal` 等（存在时） | 属于数据库状态，不在应用运行时手动删除 |
| 独立媒体副本 / ZIP 暂存 | `%LOCALAPPDATA%/Qman/library/`、`temporary/` | 写回失败或仅加载到 Qman 时保留独立副本；正常完成清理 ZIP 暂存，不随备份历史删除副本 |
| WebView2 运行数据 | `%LOCALAPPDATA%/Qman/webview/` | 内嵌界面的独立用户数据目录；不是 QQ 媒体备份 |
| 开发工具、编译缓存、合成样本 | 项目 `.local/` | 只供开发验证，不是普通用户运行所需的媒体索引 |
| 前端依赖、打包资源 | `frontend/node_modules/`、`frontend/dist/` | 开发/构建产物，不纳入 Git |

当前没有额外的持久缩略图缓存；预览响应禁止缓存。磁盘占用取决于记录数量、版本历史和运行数据，应现场统计；文件逻辑长度与磁盘分配空间要分开，不在文档硬编码本机容量。索引位置含私人路径/历史，不提交或上传；可通过设置页的“备份应用记录”保留副本。

## 预览与备份边界

PNG/JPEG/GIF 支持受限缩略图，GIF 详情可尝试动图；视频通过本机受控接口分段读取，编码是否可播依赖 WebView2。WebP/HEIC/SILK 播放尚未支持，语音先盘点与原文件备份。原件、封面、缩略图、临时资源分开显示；只见封面不能认定视频完整。

点击“备份当前筛选”，可选择当前条件、来源月份范围或整年、媒体类型，导出文件夹或 ZIP，并记住上次位置；未知、空、临时和不稳定项保留排除原因。复制后独立核对对象、大小、引用及 SHA-256，目录包和 ZIP 均不加密。

“加载备份”选择目录或 ZIP，核对账号路径并选择最外层 Tencent Files：同内容跳过，同路径不同内容加哈希后缀另存；旧备份缺少映射、QQ 仍运行或写回失败时尝试复制到 Qman 独立媒体库。保留已有时间证据，不判断 QQ 是否识别，不复制清单进 QQ 目录。

侧边栏“备份历史”支持重新定位、查看已加载媒体，以及最多 100 份本地备份的批量永久删除；删除不经过回收站，不连带删除 QQ 源媒体、已补回文件或独立副本。媒体页源删除另走明确选择与 Windows 回收站，不与备份包删除连动；没有自动云盘上传。ZIP 主要打包，创建约需三倍目标空间预算，加载也需解包暂存空间；完整说明和限制见 [媒体格式](docs/MEDIA_FORMAT.md)。

## 媒体管理与删除

媒体页点击“管理”，卡片右上角出现勾选框；支持手选、选择/取消本页、选择全部匹配结果（跨页）、排除单个文件和清空选择。按类型及顶部年份/月选择，例如“收到的表情 + 2025 年”或“语音 + 2026 年 + 2026-09”；切换条件会清空选择，翻页保留同一范围的选择。

点击“删除”先流式核对并固定清单，展示范围/数量/逻辑大小/跳过原因；明确退出 QQ 后再确认移至 Windows 回收站。执行时再核对实例和 SHA-256，回收失败不降级为永久删除，不递归删目录、不清空回收站、不连带删备份或其他副本。成功项立即从当前索引移除，原观察历史保留，可看当前账号最近任务；中断或结果不确定不自动继续。回收站恢复由用户在 Windows 操作，逻辑大小不等于立即释放空间。未稳定/临时/未知/不可读项会跳过，应先继续监控完成稳定性核对。独立备份内部视图不提供管理删除。

## 从源码构建与验证

开发需要 Go 1.25+、Node.js/npm、WebView2。依赖固定在 `go.mod` / `go.sum` 和 `frontend/package-lock.json`。

```powershell
.\tools\Build-Qman.ps1
# 另存一个版本，避免正在运行的文件被占用：
.\tools\Build-Qman.ps1 -OutputName Qman-0.6.5.exe
```

脚本将 Wails 工具和依赖缓存放在 `.local/`，安装锁定前端依赖，完成类型检查、生产构建、exe 及许可证说明。首次运行 Go 检查前应先构建前端，因为桌面入口会嵌入 `frontend/dist`。

```powershell
go test ./...
go vet ./...
```

默认测试使用合成数据，不把真实 QQ 数据送入 CI。受限 Windows 环境的文件发布权限失败与普通环境实际结果须区分。测试范围见 [TESTING](docs/TESTING.md)，兼容与实证见 [COMPATIBILITY](docs/COMPATIBILITY.md)。

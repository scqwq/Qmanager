# Qman 0.3.4 媒体管理、备份与加载使用说明

## 0.3.4 更新状态与备份盘点

- 前台更新有进度条，结束后仅用小字显示后台变化/稳定性检查。快速更新和全盘更新均提供“终止更新”；终止也会暂停后续监控，已有索引及观察历史保留，未提交批次不写入。需要时再次点击更新。
- 备份窗口的数量每 2 秒刷新；暂不纳入项直接按原因显示。尚未通过稳定性检查的文件需要继续监控；已暂停时请关闭窗口、快速更新后再试。
- “选择保存目录”独立于可备份数量，可在目录窗口中新建文件夹；路径自动记住。确认范围、类型、形式及目录后点击“开始备份”；启动失败仍保留弹窗和选择。
- 零可备份文件时空间预算为零。媒体逻辑长度、临时峰值空间与成品大小不同：当前 ZIP 创建阶段同时保留目录载荷、ZIP 和独立校验暂存，保守峰值约目录预算的三倍，目录预算另含清单预留；不代表 ZIP 最终更大或能压缩。

## 0.3.3 更新方式与缓存日期

当前账号来源提供两个按钮，不扫描其他账号或整块磁盘，范围不受当前页面类型/月筛选限制：

- **快速更新**：沿用已有清单，枚举全部受支持类型/月目录中的名字，只读取未知文件。已有普通文件不逐个打开/核对，不刷新它们的最近见到时间；关闭期间旧路径的内容替换、修改或删除可能暂时保留。运行时通知会带具体路径，受影响的旧文件/目录仍局部核对，待稳定文件分批检查。
- **全盘更新**：人工触发一次完整新增/变化/缺失核对，并保留原观察历史；随后继续快速监控。即使该来源的媒体子目录全部被删除，仍可核对空的已登记来源根；源根本身离线/不可访问则拒绝并保留缓存。

每两分钟现在只做快速目录补新，不再自动完整扫描。监听溢出、休眠/时钟跳变、读失败等会保留缺口并提示手动全盘，不静默转全量。界面分别显示上次全盘时间、沿用未核对数、实际检查数和更新数。首次快扫没有旧清单可复用，仍要读取全部未知文件；名字枚举也受目录数量/磁盘速度影响，不承诺秒开。

快速缓存只用于浏览和候选选择，不授权盲目预览/备份/删除：这些操作仍核对真实文件，备份/历史源清理还校验内容摘要。快速更新不重新写 QQ 源文件，也不删除旧观察历史。第一次导入的文件仍标“扫描前已存在”，不会把它们算今天下载。

普通来源已索引媒体的元信息存 SQLite，不复制媒体当缓存。在“新增发现日期”里，首次基线默认排除，要显式勾选“包含首次导入记录”按原首次索引日期查看；后来补入的文件会保留其真实观察时间和证据来源。

“加载备份”保存清单/落盘位置与原有时间证据，独立备份视图能按已有的首次发现日期筛，不把加载当天伪装成新增。原证据为 baseline 仍需包含首批；未保存日期保持未知。补回 Tencent Files 的新路径需回对应账号点击更新，才进入该来源的媒体索引，独立副本不自动混入原来源。

## 0.3.2 新增：从备份历史清理对应原文件

备份一直是复制，备份完成不会删除本地源文件。“备份历史”现在分成两个独立操作：

- **清理对应原文件**：使用这份备份当时实际保存的文件清单，定位本机登记的原来源，核对原实例及内容后移至 Windows 回收站。不是删除当前页面筛选出的全部文件，也不会碰恢复副本。
- **删除本地备份包**：永久删除导出的文件夹或 ZIP，不清理源文件。原有确认与保护不变。

可以先导出、手动上传云盘、删除本地备份包，再清理原文件；历史和清单仍保留。“本地包已删除”的行仍可勾选或点击清理。也可勾选同一原来源的最多 100 份备份一起预检，重复原文件只处理一次；不同来源请分开清理。

点击清理先预检，程序切换到该备份登记的原来源并在确认窗口显示账号/根目录和逐项清单。只有实际备份成功、当前索引仍为原实例且身份/路径/大小/mtime/实际 SHA-256 均匹配的文件可选；当时排除的项目、后来新增、已替换或重新出现的文件不清理。同一实例在不同备份中的内容证据冲突也跳过。确认前请手动退出 QQ，并自行确认已保留可用备份；本程序不登录云盘、不证明上传成功或云端完整。

清理成功后立即更新原媒体索引，观察历史和备份历史继续保留；备份行显示最近清理任务及联合结果，可点“查看原文件清理结果”只读查看。重复清理会重新预检，已消失或无法确认的实例跳过。移至回收站不等于立即释放磁盘空间，不会自动清空回收站。

如果备份来自另一套索引、原来源未在本机关联，或原文件已迁移/新建成另一实例，工具不按目录名/账号名猜测；此时请在媒体页手动选择核对管理。清单所在的私有索引丢失后，已删除的本地包不能凭空恢复这项历史能力。

## 0.3.1 新增：在媒体页管理与删除

1. 选择当前账号，在类型栏选图片/视频/收到的表情/语音；顶部新增年份选择。例如“收到的表情 + 2025 年”是全部来源月属于 2025 年的收到表情，“语音 + 2026 年 + 2026-09”是该来源月语音，不代表发送/下载时间。角色、状态、大小、发现日期筛选继续生效。
2. 点击“管理”，卡片右上角出现小勾选框，也可点击卡片选择。支持跨页手选；“选择本页”只影响本页，“选择全部匹配结果”包含当前条件下其他页，并可单独排除某个文件。“清空选择”重新开始，“完成管理”退出；改变条件或账号会清空选择，翻页不清空。
3. 点击“删除”只进行预检，尚未删文件。工具暂停监控、核对身份/内容并固定清单；确认窗口显示账号、真实来源根、条件、文件列表、待删除数与跳过项。确认期间新出现的文件不加入。预检可能需读取整个选中媒体内容，大视频/大批量会花时间，可取消。
4. 手动退出 QQ，核对清单并勾选确认，再点击移至回收站。执行前/过程中只读检查 QQ 进程名，不强退 QQ；如果无法核实、QQ 重新启动、文件正在占用/已变化、路径含链接或回收站不接受，会拒绝或报告失败，不自动永久删除。
5. 成功项从当前索引移除，历史仍保留。可点“查看最近删除任务”分页查看已回收、跳过、失败和待核对；重开后仍保留最近任务，不自动继续中断操作。不确定项应先核对 Windows 回收站和实际路径；再次删除需要重新选择与核对。确认清单预检完成后有效 30 分钟。

只有当前账号来源里的已识别、稳定、非临时媒体可进入待删项。首次建立索引后若还没通过稳定检查，请继续监控/核对；临时、未知、空或不可读项目本轮不删除。独立备份内部视图不提供管理删除，避免损坏共享对象；历史中的“删除备份包”仍是独立的永久删除操作。

源媒体删除进入 Windows 回收站，可由用户在 Windows 尝试恢复；程序不清空回收站、不证明立即释放空间，也不会修改 QQ 消息库。聊天中的对应媒体可能无法打开。本操作不删除其他路径副本、备份包或 Qman 独立媒体库，不依据“备份成功”自动删除。当前无法承诺并发外部改动的一致快照或账号绝无风险。

这是 Windows 试用构建。本机处理，不登录账号、不解密聊天、不注入或修改 QQ 程序、不上传媒体。盘点与备份保持源只读；只有明确选择“加载备份”并确认目标时，才尝试新增媒体，不覆盖已有文件。媒体页可显式选择源文件移至 Windows 回收站；不提供永久源删除或自动清理。

## 运行与浏览

关闭旧版窗口，双击 Qman.exe 或 Qman-0.3.4.exe。需要 WebView2；普通使用不需要 Go、Node 或数据库服务。

“选择 QQ 数据文件夹”支持外层 Tencent Files、迁移父目录、账号目录、nt_data 或 Pic/Video/emoji-recv/Ptt。自动有界发现多个来源，只索引当前账号；来源名称不是已验证昵称。新账号可点“快速更新”建立清单；重开/切账号先从 SQLite 显示旧清单，再快速补新或手动“全盘更新”。原生变化局部核对，每 2 分钟只轻量补新；缓存不代表源当前可读。

“来源月份”是文件夹标签，不保证发送/下载月份。“新增发现日期”是工具首次发现时间，默认排除首次导入时已有的文件；要查首批旧文件，请勾选“包含首次导入记录”，记录仍标“扫描前已存在”。顶部月份与侧边栏同步，日期包含结束日，更改后自动筛选，也有“查询”。

PNG/JPEG/GIF 支持受限预览，视频播放取决于编码和 WebView2；WebP/HEIC/SILK 播放暂不支持，语音先盘点和保留原文件。文件头及三次稳定性检查不保证完整下载；封面、缩略图、临时文件与原件分别管理。

## 创建备份

1. 选择账号后点击“备份当前筛选”。
2. 选媒体类型，再选“当前筛选条件”“来源月份范围”或“来源整年”。例如范围 2026-10 至 2026-10 且类型为视频，或来源整年 2025 且类型为图片。范围/整年仍沿用当前角色、状态和大小条件，不沿用发现日期。
3. 选择文件夹或 ZIP。程序显示可备份文件、分类排除原因和临时空间预算（每 2 秒刷新）；“选择保存目录”选独立输出位置，可新建并记住路径，然后“开始备份”。ZIP 主要用于单文件携带/手动上传网盘，不承诺显著压缩收益；创建和独立校验按约三倍目标预算检查空间。
4. 完成流式复制和独立 SHA-256/集合/引用校验后发布。未知、空、临时、不稳定项不复制，其原因留在清单，不能把部分备份称为全量成功。

每份包独立完整，目录包包含 manifest.json 与 objects/，必须整体保存；ZIP 包保存相同内容。两者均不加密，清单含账号相对路径和观察历史，不要公开分享。失败/取消不会覆盖旧备份；ZIP 阶段失败时可能保留已完成的目录副本，查看历史与错误提示，不把清理残留当完整包。

## 加载备份

1. 点击顶部“加载备份”，选择备份文件夹或 ZIP；先完整校验并登记历史。
2. 新包显示“账号/nt_qq/nt_data/媒体根”的相对映射。选择最外层 Tencent Files，核对账号并手动退出 QQ，再点击“加载备份”；记住已使用的目标。盘符不同没关系，不会嵌套第二层 Tencent Files，也不把清单写进 QQ 目录。
3. 同一路径同内容跳过；不同内容保留现有文件，把恢复版本加“_备份_完整哈希”后缀另存。同名目录合并，包外文件不改。
4. QQ 仍运行/进程无法核实、目标不支持安全发布、写回失败，或旧包/非标准来源没有账号映射时，尝试保存到 `%LOCALAPPDATA%/Qman/library/`。也可在对话框主动选“仅保存到 Qman”。独立副本占用应用数据所在磁盘空间，不是可随意清理的缩略缓存。
5. Qman 显示已保存的媒体和原有时间证据，无需保证 QQ 识别。不能可靠判断 QQ 聊天窗口是否恢复，不会自动回滚已补回文件。部分失败/取消保留逐项结果，可重试；中途已补回的文件不自动删除。

相同备份编号与清单重复加载只更新一个历史记录，不重复复制相同目标内容。同编号不同清单拒绝。复制同一包到别处后重新定位，会更新当前登记位置；本版不追踪该包散落在磁盘上的所有副本。加载成功后可从历史“查看已加载媒体”重新核对文件，即使原备份包已删除；若这些副本也被外部清理，会显示缺失，不补造内容。

## 备份历史与批量删除

侧边栏“备份历史”显示范围、位置、时间、大小和操作结果。位置“已登记”不表示持续联网或实时验证；移动/改名后点“重新定位”，选择完整副本重新校验，不全盘寻找。

勾选最多 100 份备份，点击“删除选中备份”，核对确认窗口列出的具体位置。此操作永久删除对应的本地备份包，不经过回收站；请确认仍有需要的其他副本。不会删除 Tencent Files 中的文件、QQ 源媒体、已加载的独立副本或网盘文件。

删除前重新核对清单/对象身份；多出文件、内容变化或链接则拒绝。任务先登记同目录隔离路径，再只删除清单对象，保留结果。中断后可再次勾选重试；失败包可能留在同目录的 `.qman-delete-*` 位置，不要自行把残留当完整备份。已删除记录保留，重复删除不会再操作。媒体页源文件删除使用下面独立的管理流程，不与备份包删除连动。

## 索引、暂停与限制

索引在 `%LOCALAPPDATA%/Qman/catalog.sqlite`，包括来源、观察历史、备份历史和加载位置；请勿删除或公开上传。点击“备份观察索引”导出元数据副本，不包含媒体或独立媒体库；当前不自动合并任意外部 SQLite。WebView2 数据在 webview/，ZIP 暂存在 temporary/，正常结束清理，异常退出残留不自动无界清理。

备份、校验、恢复和删除会暂停监控，完成后手动继续。关闭期间的新文件不会伪装为连续监控下载。没有云盘自动上传，也没有“校验成功即可安全删除 QQ 源文件”的授权状态。

合成回归和合成界面检查不代替真实 QQ 恢复识别、真实小样本一致性、完整原生窗口操作、真实编码、>4 GiB、容量不足、断盘/休眠/崩溃、长期资源和干净环境验收。本版仍为试用构建。

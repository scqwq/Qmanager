# 日期入口与首次导入记录

日期：2026-10-31。用户要求明确数据目录/类型文案、在来源月份右侧增加月份下拉，并调查昨天导入的数据按日期查询为空。

只读聚合应用私有索引确认：首批已索引文件均为 baseline。原前端已有日期 watcher，选择日期会自动查询；SQL 和独立备份内存查询都默认排除 baseline，所以首次导入当日没有后续新增时返回空。这是筛选范围和空结果提示的问题，不是未发送查询，也不能通过把 baseline 改成 live_event 来修复。

保留默认行为，新增显式 include_baseline=false 筛选参数；选中“包含首次导入记录”后，按原 first_seen_at 查询已存在文件。仍显示“扫描前已存在”，不修改持久时间、实例 ID、来源月、可信度、媒体或文件系统属性。baseline_files 提供当前日期/类型/角色/大小等条件下首批匹配数，空结果可解释并一键显示，不能用其他账号或其他日期的总数误导用户。

月份下拉与侧边栏使用同一选择值。来源视图按 source_month，发现视图按首次发现的本地月份；月份选择清除日期区间，日期输入清除月份限制，防止残留的来源/发现月与日期范围交叉导致空结果。日期仍自动筛选，另提供查询按钮、查询状态、日期顺序检查和清空筛选。

查询和显示支持 SQL 缓存与独立媒体包视图，含首次导入的选择也随备份选择条件保存，但不改变媒体包主版本和观察证据语义。旧包省略该字段时默认 false。

入口按钮统一“选择 QQ 数据文件夹”，说明最外层 QQ 目录导入的是媒体清单、不复制原文件；类型入口称“全部类型”。不增加真实发送时间/下载时间推断，不扫描新范围或增加源写入。

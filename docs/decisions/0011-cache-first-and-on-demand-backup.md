# 0011 — 缓存优先补新与备份按需核对

日期：2026-11-01。用户确认快速更新沿用缓存、只识别新路径，备份不应等待全账号旧待稳定队列。本决策替代0010中数据库待稳定队列自动轮转部分。

查询/筛选不触发扫描。快速遍历受支持目录名字，与已缓存路径集合比较，不打开已知普通文件；既有修改/替换/缺失留待全盘核对，运行时明确通知仍处理具体路径。不用目录mtime推断完整变化，不引入USN/提权服务。新发现或变化的非baseline文件最多128个会话内跟进项；首次基线/历史pending/未跟进项不自动补领。

备份计划区分直接可用、待核对候选和排除。候选非零就可启动异步任务：停止监控，按原筛选冻结实例；仅打开这些实例，核对身份/大小/mtime，成功观察通过局部Apply保留首次发现与历史，最多补三轮且轮次间隔至少一秒。已变/不可读/实例不符/未稳定项以固定实例ID额外排除，不改写原筛选或让失败项静默消失。无可用项不发布。Build仍拒绝未稳定项，保留复制前后检查、SHA-256和独立包验证，不借缓存跳过校验。

额外排除只会收紧Build资格，不能将原本不合格的文件变成可备份。格式仍qman-media-directory v1，新增的排除原因沿用现有字符串字段；没有源sidecar、SQL或权限变更。真实源不用于自动验收。

定时循环仅把ticker当唤醒信号，使用实际处理时刻；业务耗时与空闲长停顿分开，保留时钟漂移及原生异常的覆盖证据，避免旧通知误判时钟倒退。真实休眠/断盘完整验收仍待验证。前台取消叫终止更新，后台叫暂停监控；弹窗按索引revision刷新，不做无变化的定时全体统计。
